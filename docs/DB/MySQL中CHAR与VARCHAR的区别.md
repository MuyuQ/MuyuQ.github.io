# MySQL中CHAR与VARCHAR的区别详解

## 基本区别

1. **CHAR**固定长度，**VARCHAR**可变长度。

2. 如果实际存入数据长度小于指定长度，CHAR会填充空格到指定长度，VARCHAR会缩短到实际长度。

3. 如果实际存入数据长度大于指定长度，严格模式下会报错，非严格模式下会截断并产生警告；MySQL 5.7+默认启用严格模式。

4. 在存储定长的短字符串、引擎采用定长行格式等场景下，CHAR的效率比VARCHAR高，但相对而言更费存储空间。VARCHAR需要用额外的字节记录实际长度：最大长度不超过255字节时用1个字节，可能超过255字节时用2个字节。每次修改完数据后还需要重新计算长度，带来额外开销。

5. 空间分配方式与存储引擎有关：CHAR在内存和硬盘上都会按照最大的指定长度分配空间，而VARCHAR在硬盘上会按照实际长度分配空间，在内存上按照指定长度分配空间（如MEMORY引擎就把VARCHAR按定长存储）。这导致两个问题：

   - 若将 VARCHAR 的指定长度设置得过大，会导致内存占用过高，反而不利于性能。

   - 若定义 `VARCHAR(30)`，修改前字符长度为 10，系统分配了 10 个存储单位；修改后字符长度变为 20，虽然仍在最大长度范围内，但原存储位置可能无法满足新的存储需求，系统需要进行额外操作，如拆分和分页。

6. 存储引擎与场景推荐：

   - **MyISAM**表推荐使用CHAR，缺点是占用磁盘空间。
   - **InnoDB**表推荐使用VARCHAR。
   - 如果存储的信息很短，推荐使用CHAR，因为VARCHAR还有额外的开销。
   - 如果是长度固定的数据（如UUID、MD5摘要、身份证号），CHAR更适合。
   - 如果是频繁改动的字段，推荐使用CHAR，因为VARCHAR每次都有额外的长度计算工作。
